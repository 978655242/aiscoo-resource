# Aiscoo Web account entry

The product composition never creates the upstream browser OAuth owner and never reads, clears or migrates its saved credentials. Unsupported remote and share callback routes report Aiscoo sign-in unavailable before callback parsing or relay admission. Missing or invalid account origins fail closed with a fixed configuration message.

Only the existing exact loopback browser New API authority may serve local login. Its PKCE, SID, generation and refresh remain unchanged. Same-session pages receive independent admitted connection scopes from the existing Host owner. This module does not extend callbacks, CORS, pairing, relay or Host state. Its local Web startup composition projects the browser account connection lifecycle into a connecting, account-mismatch, legacy account-in-use or disconnected page with a reload action; it does not change the account owner.

Public shares use the existing loader and readonly renderer with anonymous fetch (`credentials: omit`, redirects rejected). Protected or hidden/not-found shares report that Aiscoo sign-in is unsupported, without official provider controls or old account hints. The loader owns view state only; it never accepts a session or credential.

`createAiscooBrowserWebStartup` renders a connecting page before admission and a localized account-mismatch, legacy account-in-use or disconnected page on failure. A new conflicting account remains on an explicit-retry page without automatic reload. Only a mismatch page whose local account has no confirmed owner receives the optional `onLogin` command: it directly reuses that same account's `oauth.startOAuth(new-api)` and navigates the current page to its authorizeUrl, without another restore, Host RPC, connection or credential owner. Its PKCE proof stays in this page's existing sessionStorage. A confirmed different owner receives only the mismatch explanation and Retry; disconnected and legacy occupied pages do not receive this login command. The unconfirmed page uses a localized Aiscoo sign-in heading, the standard `oauth-login-button-new-api` button, a busy state and a fixed localized failure message, never a raw error or authorization URL. An admitted connection closed with account-changed reloads the current entry exactly once after the adapter has aborted its forward RPCs and disposed its reverse account channel; no stale services can be delivered afterward. It forwards lifecycle ownership to the browser account connection adapter. The same startup retains page lifecycle cleanup after the connection has closed, so a local login is an explicit new page command rather than reopening that connection. Duplicate login commands share one attempt; a failed command may be tried again, while successful navigation keeps the controls busy. Retry, dispose or beforeunload terminates page commands, and a late authorize result cannot navigate after that boundary or while the page is unloading. Before unload it disposes the connection without showing a failure or reloading; its terminal flag prevents the main bootstrap catch or late service completion from replacing the error page with an old Root. Retry reloads the current entry; it never clears login storage, retries OAuth code exchange or silently displaces another page.
